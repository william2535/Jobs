# Jobs Android / Google Play builds

The Android release source is on `release/jobs-android`. The existing web app branch and hosted website are separate. The Android app bundles the validated Vite output and does not need the website for first launch or offline work.

## Identity

- App label: **Jobs**
- Application ID: **`com.willflood.jobs`**
- Initial version: **1.0.0**, version code **1**
- Minimum Android: **7.0 / API 24**
- Target / compile API: **36 / Android 16**
- Upload certificate: `android-play/upload-certificate.pem`
- Expected certificate fingerprint: `android-play/signing-certificate.json`

This is a first Android package. Do not replace an established Play app with a different package name or upload key. The signed `.aab` is the upload file; Google Play testing, listing, policy declarations and review are separate.

## One-time signing setup

Keep **Jobs-signing-backup-private.zip** privately. It contains the encrypted upload keystore and the configuration needed to use it. Do not upload that ZIP to Google Play, attach it to an issue, or commit it to a repository.

1. Download the private signing backup supplied with the first build.
2. Upload that ZIP into your own Google Cloud Shell, using its Upload file control.
3. Extract it into a private folder and run the included configuration script with your already authenticated GitHub CLI:

```sh
mkdir -p ~/jobs-signing
chmod 700 ~/jobs-signing
unzip -n ~/Jobs-signing-backup-private.zip -d ~/jobs-signing
node ~/jobs-signing/configure-github-signing.mjs ~/jobs-signing/signing.json
```

The script saves four encrypted Actions secrets in **william2535/Jobs**. It sends values through standard input and does not print them. This is needed once, not for each build.

Required secret names: `JOBS_UPLOAD_KEYSTORE_BASE64`, `JOBS_UPLOAD_STORE_PASSWORD`, `JOBS_UPLOAD_KEY_ALIAS`, `JOBS_UPLOAD_KEY_PASSWORD`.

## Build future upload files in the browser

1. Open the Jobs repository → **Actions** → **Build Jobs for Google Play**.
2. Choose **Run workflow**. Leave the version-code box at **0** for automatic numbering.
3. Open the completed run and download its **Jobs-Play-upload-…** artifact.
4. Extract the ZIP. Upload its `.aab` to the appropriate release in Google Play Console.

The workflow checks out `release/jobs-android`, tests it, uses the existing upload key, validates the bundle and supplies the files. It never submits a Play release or changes the existing hosted web app. New builds use `1000 + workflow run number`; a retry of the same run keeps its number. If a particular code was already uploaded, start a new run rather than retrying the old artifact. Every update must use a code higher than all codes previously uploaded to Play. If you previously chose a high manual code, enter a higher manual code until automatic numbering exceeds it.

When changing the app, commit the intended changes to the Android release branch before building. Incorporate later changes from `feat/offline-jobs-mvp` deliberately, preserving the native integration and checking the diff. A new `.aab` contains the code at the time it was built; an old file cannot acquire new app features by itself.

## Build locally or in Cloud Shell

Prerequisites: Node 22.12+ (24 recommended), JDK 21, Android SDK platform 36 and Build Tools 36.0.0. The Gradle wrapper pins 8.14.3 with a distribution checksum. Android Gradle Plugin is pinned to 8.13.2.

```sh
npm ci
npm test
JOBS_SIGNING_CONFIG=/absolute/path/to/signing.json npm run android:release
```

For a local update, provide an integer version code higher than every code previously uploaded to Play. The following example is valid only if the highest uploaded code is still `1`; after an automatic `1001` or higher build, choose a larger value instead:

```sh
JOBS_VERSION_CODE=2 JOBS_SIGNING_CONFIG=/absolute/path/to/signing.json npm run android:release
```

Output: `release/android/Jobs-<version>-<code>.aab`, the matching direct-install `.apk`, SHA-256 files and `BUILD-RECORD.json`.

The build verifies the exact upload certificate before signing. A new key is never silently generated by the build. Store secrets outside this repository. Only validated `dist/` files are copied into the Android package; the private customer example at the repository root is excluded.

## What the Android package preserves

- Existing Jobs interface, job/site data formats and IndexedDB schema.
- Offline first launch through a fixed app-local HTTPS origin.
- Document and photo imports through Android's file picker.
- Chunked JSON exports through Android's save dialog, including cancellation/failure handling.
- Prepared service reports through Android printing / Save as PDF.
- App-aware Back handling, unsaved-work protection and stable storage across ordinary updates.

The Android workspace is separate from the browser workspace. To move existing work, export a workspace backup in the website and restore it in the Android app. Uninstalling or clearing app storage can remove its local records. Export a backup before switching between a directly installed test APK and a Play-installed version: Google Play may use a different app-signing key, requiring removal of the test installation.

Zone Sketch uses the manual drawing export/import workflow in Android. The existing optional popup handoff cannot return through an external Android browser. Reports remain draft service records, not validated compliance certificates.

## Verification before a public rollout

See `docs/android-verification.md` for the actual build checks and any outstanding device checks. Exercise offline launch, save/reopen, photo import, backup save/cancel/restore, Android Back, Save as PDF, and an upgrade preserving data. A successful bundle build is not proof that all native device behaviours passed.
